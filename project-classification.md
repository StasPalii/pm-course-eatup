# Класифікація проєкту та аналіз проєктного оточення

**Проєкт:** EatUp — система попереднього замовлення страв в університетській їдальні з отриманням замовлення через QR-код.

---

## 5.1. Класифікація проєкту

| Ознака класифікації | Обрана категорія | Обґрунтування |
|---|---|---|
| Розмір проєкту | Малий | Проєкт розробляється студентською командою з трьох осіб у межах навчального курсу без зовнішнього фінансування. |
| Тип продукту | Вебзастосунок | EatUp реалізується як простий вебзастосунок, доступний через браузер комп'ютера або смартфона. |
| Галузь застосування | Громадське харчування / Освіта | Продукт призначений для спрощення замовлення страв в університетській їдальні. |
| Рівень невизначеності вимог | Низький | Основні функції визначені заздалегідь: перегляд меню, кошик, оформлення замовлення та QR-код. |
| Модель співпраці | Внутрішній продукт (навчальний проєкт) | Проєкт виконується студентською командою без зовнішнього замовника. |
| Тип життєвого циклу | Ітеративний / Agile | Функціональність реалізується поступово, з перевіркою результатів після кожного етапу. |

---

## 5.2. Аналіз внутрішнього оточення

- **Склад і компетенції команди.** Команда складається з трьох учасників: Палієнко Станіслав Олександрович — Product Owner / Project Manager (Team Lead), Довгополий Олександр Романович — Analyst, Труш Ігор Анатолійович — Developer.
- **Наявні технічні ресурси.** Для розробки використовуються Visual Studio Code, GitHub, HTML, CSS, JavaScript та прості інструменти для зберігання даних.
- **Часовий бюджет команди.** Розробка виконується паралельно з навчанням, тому основна увага приділяється реалізації мінімально необхідних функцій.
- **Досвід учасників з обраною тематикою.** Для створення продукту достатньо базових знань веброзробки. Складні платіжні інтеграції та зовнішні API не передбачаються.
- **Організаційне середовище.** Проєкт виконується в межах університетського курсу. Завдання розподіляються між учасниками відповідно до їхніх ролей.

## 5.3. Аналіз зовнішнього оточення

- **Цільова аудиторія та її потреби.** Основна аудиторія — студенти університетів, які хочуть швидко переглядати меню та замовляти їжу без очікування в черзі. Додаткова аудиторія — працівники їдальні, які обробляють замовлення.
- **Наявні аналоги та конкуренти:**
  - *Glovo* — сервіс замовлення їжі, який має широкий функціонал, але переважно орієнтований на доставку.
  - *Bolt Food* — платформа онлайн-замовлення їжі, яка також спеціалізується на доставці.
  - *Електронні меню закладів харчування* — дозволяють переглядати страви, але не завжди підтримують попереднє замовлення.
- **Технологічні тренди.** Використання електронних меню, QR-кодів та простих вебзастосунків для автоматизації обслуговування.
- **Регуляторні чинники.** Для навчальної версії використовуються тестові дані без зберігання платіжної інформації. Збирається лише мінімальна інформація, необхідна для оформлення замовлення.
- **Партнерські системи/API.** На початковому етапі інтеграція зі сторонніми сервісами не передбачається. QR-коди генеруються за допомогою готової бібліотеки.

## 5.5. Висновки

EatUp є малим навчальним вебзастосунком із чітко визначеним базовим функціоналом. Для його розробки обрано ітеративний підхід Agile, який дозволяє поступово створювати та перевіряти окремі можливості системи.

Основними обмеженнями є невелика команда, обмежений час розробки та відсутність бюджету. Тому було вирішено відмовитися від складних функцій, зокрема онлайн-оплати, авторизації, особистих кабінетів та інтеграції зі сторонніми сервісами.

Мінімальна версія EatUp передбачає перегляд меню, додавання страв до кошика, оформлення замовлення, генерацію QR-коду та просту сторінку для перегляду й підтвердження замовлень працівником їдальні.

Основними ризиками є помилки під час оформлення замовлень та генерації QR-кодів. Для їх мінімізації передбачається тестування кожної функції окремо.

Наступні кроки: створити інтерфейс меню, реалізувати кошик, додати оформлення замовлень, генерацію QR-кодів та сторінку працівника їдальні. Розширення функціональності можливе після завершення базової версії.
